# 可直接交给 agent 的改造任务

使用方法：将下文任务复制给能访问 TO DO 源码与原工作流的 agent，并填写路径、可运行样例与约束。无需先把原工作流改造成黑板样式。

---

请将我已经完成的视频生成工作流改造成可拖入 TO DO 安装的扩展。保留原工作流的视觉质量、核心算法、提示词与随机种子行为，先理解它再改造。

输入资料：

- TO DO 仓库路径：由我提供。
- 原工作流路径与入口命令：由我提供。
- 测试素材、预期输出、依赖与环境配置：优先从原目录读取；缺少关键资料时具体指出，继续完成不依赖它的适配工作。
- 目标编辑等级：至少 E1，各逻辑元素可单独调整位置、缩放、旋转、透明度和宿主动效。需要原生文字编辑或内部动画参数时评估 E2/E3。
- 我额外要求保留的行为、平台、付费调用权限：按我的实际说明执行，不自行消耗未授权远程资源。

先读 `docs/workflow-to-extension.md`、`docs/extension-authoring.md`、`docs/extension-self-check.md` 与 `docs/render-export-performance.md`，再检查实际 manifest 校验器、production 请求/结果/缓存和时间轴入轨实现。文档不是允许凭空创造字段的依据。

按以下步骤完整交付：

1. 审计原工作流，写出输入、阶段、中间产物、对象 ID、坐标、时间基准、参数和依赖；用最小样例记录原结果。
2. 写出原命令实际决定的音色、语速、停顿、分镜、素材、运动、转场、音乐和时间。这些效果必须留在成品里。宿主现有的配音、分镜或生图会改掉其中任何一项时，用 preserveSource 委托原入口，并改宿主校验与生成层。不要为了接上 scene-clips 换成宿主默认音色、黑板排版或淡入贴纸。
3. 能在不改变成品的前提下拆出独立透明层、背景和声音时，再做逐元素入轨。拆开会改变成片时，先把原成片放进时间轴，并在迁移报告里写明哪些对象还不能拆。
4. 原工作流有完整出片命令时，把脚本、字体、BGM、特效等可分发文件打进扩展包，skill.json 写 preserveSource 指向包内入口（不要依赖作者机器绝对路径或外部项目目录）。配音/生图走 TO DO 已有服务。只有原阶段本来就是逐镜头透明层时，才把产品入口做成 render.py 的 scene-clips。自检用的协议探针可以另留，探针的画面不是成品。写真实媒体到 outDir；不要直接操作工程 store。
5. 参数逐项映射到 UI、消费代码、受影响层与缓存输入。检查新参数能使缓存失效；不能以修改包版本代替正常参数变化。检查任意 per-element 位置/动画字段确实有宿主文档、编辑、请求、缓存、UI、入轨消费链路。
6. 如需要“重生成后保留所有手工动效”，检查并完善 productionTimeline 的状态合并。现有媒体路径只保护部分几何变换，不能宣称自动保留全部关键帧/效果；draw/hold 也不自动共享贯穿关键帧。
7. 在安装目录测试依赖与路径。不要在包里包含密钥、作者机器绝对路径、运行缓存或大模型。安装不执行原工作流或依赖安装。
8. 为扩展编写 extension.check.json（参考 docs/templates/extension.check.json）与真实测试脚本；迁移 origin=migration 必须测原工作流基线、真实协议/产物、缓存、入轨、逐元素编辑和导出。通过 npm run extension:check -- <源码目录> <目录外报告.json> <目录外包.todoext> 运行验收并打包。安装成功、生成成功、逐元素可编辑分别验收。
9. 验证元素编辑、时间对齐、重复同步、局部重做、缓存、升级与 TO DO 导出。只完成 mock 测试时明确指出真实运行尚未验证。
10. 审计原工作流的渲染/编码/I/O，不原样搬入低效 Python 逐帧循环。根据任务选择 FFmpeg、宿主 Canvas、向量化/原生计算或必要的 Python 自定义渲染；复用静态资源与分层缓存，有独立重任务就实现有界并行/流水线。固定输入/画质/环境，冷启动和热缓存各测至少三次，保留原流程或串行参考与新流程对比。添加性能检查、PERFORMANCE.json 与预算断言；预算或质量未通过继续修复，不能降画质、删除逐元素编辑、虚构加速或无理由串行。报告线程/内存/显存/背压/取消与不能并行的原因。

强制闭环：任何检查 FAIL/退出非零/缺证据都不得交付为已完成。读取报告与日志，修复原因，单项验证后再次运行完整 extension:check，直到最新报告 ok=true、退出0；不能删检查、降低断言、用旧产物或反复空跑掩盖失败。确实缺依赖/凭据/资料时明确报告未通过的阻塞，继续其他工作，不得伪造通过。所有源码与宿主改动后重新验收。交付报告内的包 SHA-256 必须对应实际提供的 .todoext。

请按 `docs/templates/workflow-migration-report.md` 输出 `MIGRATION.md`，包含路线与阶段归属、参数映射、逻辑元素到产物/轨道映射、时间/坐标基准、依赖、宿主缺口与改动、测试证据和已知边界；交付可安装包、完整源码、样例与复现命令。涉及宿主适配的包必须同时交付宿主改动与兼容说明。不要只给我一个推荐方案或压缩包外壳。
