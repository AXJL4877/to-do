## 0. 给接手智能体的执行摘要

用户要的是可以连续完成每日内容生产的软件：从需求、口播稿、配音、图片/封面到剪辑输出，步骤清楚、信息完整、异步任务不打断工作、界面可调整、动效有质感、长工程仍流畅。仅修几个按钮、换配色或通过构建，不构成完成。

必须同时交付以下结果：

1. **可靠的口播创作系统：** 正文与元信息分离；手改不会被 AI 或阶段切换覆盖；可以选题、改结构、逐段生成、审阅修改、回退、定稿、交给配音和发布。
2. **完整的全局交互改造：** 工作区、属性栏、媒体库、AI 面板、浮窗、弹窗、发布台采用一致的布局、缩放、滚动、操作和反馈规则。
3. **持续可用的后台生产：** 图片、视频、配音、封面等任务有明确归属和状态，支持离开面板后继续、恢复查看、失败重试、部分成功保留，不重复入库或写错工程。
4. **可信的进度与动效：** 不裁切关键信息，不伪造百分比；短动效辅助理解；支持减少动态效果；高频播放不受装饰动画拖累。
5. **经过测量的性能：** 有代表性工程、冷/热缓存区分、主线程和内存数据、前后对比、截图与回归证据。

执行顺序：基线与数据安全 → 正文/阶段一致性 → 后台任务及归属 → 全局布局与动效 → 性能专项 → 集成验收。每一步都必须保留已有可用能力。

### 1.3 已确认缺口

1. `script` 混入项目/选题/素材/发布文本；字数统计和下游读取可能把元信息当作口播。
2. `buildMemoFromWorkspace()` 优先读取阶段草稿，手改编辑框没有可靠地更新草稿，后续阶段可能覆盖手改。
3. `extractMemoBody()` 当前会把 `--- 发布 ---` 后的内容也读作正文。
4. 局部改写 `runAi()` 缺少与阶段请求同等的生命周期保护；返回时直接利用编辑框当前位置和内容，有并发编辑冲突风险。
5. `HistoryNode` 主要记录动作元数据，不能直接作为可恢复的完整历史快照。
6. 多个面板各自轮询 AI 任务；需核实去重、页面卸载、后台导入及多窗职责。
7. 入库流程存在先 ACK 再本地处理的路径，需故障注入验证：若后续保存失败，产物是否仍可恢复。
8. 发布流程存在多个异步分支，资产/工程切换后的旧响应、成功结果保留、标题与封面一致性没有整体证明。
9. 工作区左右栏目前有 420px 上限，底部 dock 有 360px 上限；这些常量未按内容和视口统一求解。
10. 全软件高负载性能、混合媒体预览、DPI、多屏、完整动效与实际 AI 端到端流程尚未验收。

## 2. 产品目标、用户与成功定义

### 2.1 核心用户与任务

| 用户/场景 | 需要完成的工作 | 成功表现 |
| --- | --- | --- |
| 每日口播创作者 | 从一句主题生成可直接朗读的稿子 | 随时知道当前阶段、哪些已确定、下一步做什么 |
| 已有稿件用户 | 粘贴稿子，局部改写、压缩、润色 | 不强迫从头走选题，不覆盖原稿，修改可审阅与撤销 |
| 图文/视频制作用户 | 同时生成配音、封面、插图并剪辑 | 任务在后台运行，编辑界面不被锁死 |
| 长工程用户 | 管理多轨片段和大量生成结果 | 搜索、切换、拖动和预览有稳定响应，关键信息不被截断 |

### 2.2 商业化体验在本项目中的定义

“商业化”在本次指可靠性、一致性、可恢复性、可理解性、视觉品质和经过验证的性能，不代表要求加入收费、账号或营销功能。

- 完整闭环可用，失败时知道发生了什么、产物在哪里、下一步怎么做。
- 不因切换页面、缩放窗口、返回编辑、网络波动而丢稿或写错工程。
- 主要操作有名称，当前状态和操作结果可见，无需猜图标含义。
- 常用操作省步骤；高频操作不能被非必要对话框打断。
- 所有核心页面采用统一视觉和交互规则，不仅精修口播单页。

### 2.3 范围边界

本次包含现有桌面应用、口播生成、媒体/AI 任务面板、配音与字幕入口、封面/发布准备、工作区面板、时间轴整理、预览及动效/性能改进。

本次不要求重写渲染引擎、迁移前端框架、建设多人协作、支付、云账户、自动抓取每日新闻、自动公开发布、数字人或完整移动端。日更表示高效重复生产，不等同于未经用户指令自动定时生成或发布。不要为满足“商业化”添加这些范围外功能。

## 3. 信息架构与页面职责

### 3.1 主工作流

```text
创作需求 → 口播工作台 → 正文定稿
                         ├─ 配音任务 → 媒体库/时间轴 → 字幕
                         ├─ 发布标题/简介/标签 → 封面任务
                         └─ 插图/视频/动态文字任务
                                      ↓
                           编辑工作区 → 预览 → 导出 → 发布准备
```

任务中心贯穿全部步骤。离开某个页面只改变视图，不自动取消后台任务。工程是内容、任务归属、素材与版本的组织边界。

### 3.2 页面职责表

| 页面/区域 | 主要职责 | 不应承担的职责 |
| --- | --- | --- |
| 项目起始页 | 新建、打开、最近项目与可恢复状态 | 启动即执行上次未确认的生成/发布 |
| 口播工作台 | 创作设定、正文编辑、AI 决策、历史和交付 | 混排调试参数、项目说明与最终朗读正文 |
| 编辑工作区 | 媒体、画面预览、属性、时间轴 | 每帧刷新完整 AI 任务列表 |
| AI 面板 | 提交生成、参考素材、当前结果和快捷修改 | 作为后台任务运行唯一依赖的挂载组件 |
| 全局任务入口 | 运行数量、错误提示、任务中心 | 用密集 toast 代替长期状态 |
| 任务中心 | 查看、筛选、恢复、重试、定位产物 | 把“关闭记录”误当取消生成 |
| 发布准备台 | 明确当前资产，编辑元信息，生成/选择封面 | 未经确认直接对外发布 |
| 设置 | 预览质量、缓存预算、动效偏好、任务并发配置 | 把内部实现细节塞到每次生成的主路径 |

### 3.3 统一操作规则

- 每个工作区同时只有一个视觉上最突出的主动作；“重新生成”“跳过”“更多”作为次动作。
- 主动作应命名为结果，如“确认选题”“应用 3 项修改”“生成配音”“生成封面”，不能只显示箭头或“发送”。
- 首次进入提供简短说明；用户开始工作后不重复占据大面积空间。
- 一般设置立即保存或有明确保存状态，不能同一页面部分自动保存、部分静默丢弃。
- 仅影响局部内容的错误就地展示，保留输入；跨任务问题进入任务中心，不弹连续阻塞框。
- 普通生成可重复提交不同任务；同一次点击/网络重试必须幂等，不得重复计费或重复入轨。

## 4. 口播工作台布局与内容分区

### 4.1 页面构成

```text
┌ 工程/稿件名称 · 保存状态 · 正文字数/时长 · 历史 · 交付动作 ┐
├ 阶段导航：立项 / 选题 / 素材 / 结构 / 成稿 / 定稿          ┤
├ 创作设定（可展开）：目标、素材、结构、来源与约束           ┤
├ 正文编辑区：只显示可朗读内容；明确当前编辑范围             ┤
├ 可拖动分隔线                                              ┤
├ AI 决策区：当前问题、候选、对比、错误/生成状态              ┤
└ 固定操作区：自定义要求 / 次动作 / 当前阶段主动作            ┘
```

宽窗口允许创作设定以侧栏呈现；窄窗口使用折叠区域。正文和 AI 区域始终存在可访问的入口，不为适配窄窗口静默隐藏输入或确认按钮。

### 4.2 正文与元信息契约（TXT-01，P0）

1. 正文必须有唯一权威数据源。项目、素材、大纲、发布标题、封面文字、标签均是独立元信息，不直接拼进可编辑正文。
2. 字数/时长只统计正文；选区统计只统计选中文字。沿用默认 4.5 字/秒，明确为估算，可配置语速；最终配音时长以音频为准。
3. 复制正文、送配音、送字幕、送正文润色只能取得正文；“复制完整创作简报”可单独提供。
4. 原始材料标识可用于内部引用，但不可被 TTS 当朗读内容。资料出处在创作设定/引用区可查。
5. 空字符串是用户明确清空的合法正文，不能用 `oldBody || generatedBody` 把旧稿恢复回来。
6. 旧格式中的正文标记与发布标记需要迁移；没有标记的普通文本按原稿保留，不得被识别为空稿。
7. 迁移前保留原文与 schema 标记，重复打开不再次迁移；不能因正文恰好包含类似横线而随意截断普通稿。
8. 迁移不依赖当前编辑器是否打开；下游读取也应经过统一正文访问层。

### 4.3 手动编辑契约（TXT-02，P0）

- 手改后，后续 AI 输入必须读取当前稿件版本；确认其他阶段不得覆盖手改。
- 保留段落 ID 和结构关联。跨段插入、删除、合并以及粘贴多段文本必须保持用户看到的完整文字；不能用“按空行重新分配大纲”导致丢段。
- 用户没有改动的段落尽量保留对象身份，避免全文更新触发所有段落重绘。
- 连续输入合并成编辑事务，不每个字符保存一个永久版本。失焦、显式保存、AI 应用和阶段确认形成可恢复边界。
- 正文编辑与阶段状态持久化保持一致；不能一份写入成功、另一份仍是旧稿而没有恢复机制。
- 普通编辑支持撤销/重做，AI 应用作为一次事务可整体撤销；与时间轴撤销栈区分，焦点决定作用域。

### 4.4 创作设定面板（TXT-03，P1）

展示目标平台、受众、时长/目标字数、口吻、目标、禁区、素材引用、选题主张及大纲。默认展示摘要，可展开字段和来源。字段标题应是用户语言，不能显示 `duration_sec` 等内部键。

修改上游设定时，说明受影响的后续结果。先保留现有正文并标记“基于旧设定”，由用户选择重新生成相关阶段；不自动清空整稿。

## 5. 六阶段口播流程详细规格

### 5.1 启动模式（SCR-01）

| 模式 | 输入 | 行为 |
| --- | --- | --- |
| 标准创作 | 一句话主题/目标，可带素材 | 完整六阶段，按需确认重要决策 |
| 快速创作 | 主题与少量设定 | 使用默认值合并低价值确认；选题、结构、最终稿仍有明确确认点 |
| 打磨现稿 | 非空正文 | 直接进入修改审阅与复核，不重走立项选题 |

存在正文时开始新创作，必须保存当前版本并明确“新建稿件版本”或“继续现稿”。不允许直接把当前内容换成空白模板。日常默认可记住平台、时长和口吻偏好，但不能把前一期主题、来源或结论当成新一期事实。

### 5.2 阶段规格

| 阶段 | 输入/界面 | 用户动作 | 确认后产物 | 关键校验 |
| --- | --- | --- | --- | --- |
| A 立项 | 主题、平台、时长、受众、口吻、目标、禁区；真实表单 | 修改字段；使用推荐；确认创作设定 | Project brief 与目标字数 | 必填项、数值有限且范围合理；编辑值优先于 AI 推荐 |
| B 选题 | 3–5 个有区分的选题，标题、主张、角度、原因 | 选择、自定义、基于选题再展开 | 确认的 Topic | 不把多个候选都写入正文；评分只作参考而非真实性背书 |
| C 素材 | 问题清单；粘贴材料及来源；待补信息 | 选择保留、补来源、删除、声明仅创作类比 | 材料库与引用 | 用户粘贴/AI 推断/有来源事实必须区分；无来源不自动标 verified |
| D 结构 | 钩子、主张→下一问→支撑、大纲 | 编辑逻辑字段、调整顺序、确认结构 | 稳定段落 ID 的 Outline | 修改主张时保留对应材料引用；不能静默重排锁定段落 |
| E 成稿 | 分段候选、已确认稿、整体打磨对照、复核清单 | 按段确认/重试；接受或拒绝修改；处理问题 | Draft revisions、审阅决定、复核状态 | 不丢段；拒绝全部合法；重复原句不得错替换；事实处理必须对应实际动作 |
| F 定稿 | 正文、估算时长、目标偏差、未决问题、发布元信息 | 标记定稿、复制正文、送配音、去封面/发布准备 | 可追踪的 finalRevision 与下游任务来源 | 明确人工确认点；未决事实/超长问题显式提示；不自动发布 |

### 5.3 候选和表单（SCR-02，P0）

- `form`、`single_select`、`multi_select`、`variants`、`diff_review`、`rank`、`free_input` 每种卡片必须有对应行为或显式受控降级，不能都套成普通单选按钮。
- 长候选默认可显示摘要，但必须提供完整正文的展开/阅读方式；不得在数据层截掉 160 字后再无法查看。
- 显示推荐理由、风险/约束和关键差别。推荐可取消，不得在用户清空选择后偷偷回退推荐。
- 单选使用 radio 语义，多选使用 checkbox 语义，选中状态不能只靠颜色表示。
- 表单建议值可改，选择列表允许合理自定义；必须验证真正提交的值，不只验证控件显示。
- 多选“全部不采用”在审阅类步骤是合法决定；材料门禁不通过时说明缺什么，不自动替用户选择全部。
- 自定义文字必须区分“直接采用这个内容”和“要求 AI 重新生成”；不能所有自然语言都自动进入新一轮生成。
- IME 输入期间 Enter 不提交。默认 Enter 提交短要求，Shift+Enter 换行；长正文的 Enter 始终换行。

### 5.4 局部改写与审阅（SCR-03，P0）

选中文本可改写、缩短、扩写、解释或提问；未选中时明确作用于全文。请求提交时保存正文版本、选区范围、原文和工程/稿件 ID。

返回时：

1. 当前版本和作用范围未变化：展示建议/差异，用户应用后作为一个可撤销事务。
2. 版本变化但能严格确定对应范围未变：允许在原范围应用，并显示实际范围。
3. 范围无法确定、正文已变、工程已切换：不得自动写入；把建议保留为“基于旧版本”，提供复制或重新生成。
4. 用户关闭建议面板/退出当前编辑：取消订阅或请求，不再弹回已关闭面板；已产生的收费后台任务保留到任务中心。
5. 取消、超时、网络失败与内容校验失败分别显示，不把主动取消报成系统错误。

打磨审阅必须显示修改前、修改后和原因，可单条接受/拒绝、全部接受/拒绝。只应用所选修改；锁定段落不可被 AI 修改。跨段建议要么准确支持，要么明确阻止并保留原稿，不能静默部分应用。

### 5.5 阶段回退与版本恢复（SCR-04，P1）

- 阶段导航展示未开始、进行中、已确认、需重新确认、失败状态。
- 点击已确认阶段可以查看当时内容；选择“从这里修改”后创建新的历史节点，不销毁后续历史。
- 回退保存实际可恢复的数据快照或等价操作日志，包括正文、设定、结构和审阅选择；动作标签本身不算恢复能力。
- 可恢复每个确认节点和最近手动编辑事务；历史列表显示时间、阶段、改动摘要与字数。
- 限制历史体积：最近 50 个自动节点加用户命名版本；超过时合并自动节点或归档，不能静默删除命名版本。保留策略必须在保存/重开测试中验证。
- 已提交任务固定引用提交时版本；回退正文不改变已运行任务的输入快照。

### 5.6 素材与事实处理（SCR-05，P0）

程序必须区分“有来源”“待核验”“已人工核验”“创作类比”。模型返回 `verified=true` 不等于外部已核验事实。未提供搜索服务时，不显示“联网核查完成”。

处理无来源/不一致断言的动作包括：补充来源、改为非事实表达、删除断言、记录人工核验。只有动作真实完成后才解除对应提示；不能仅勾选“已处理”却保留未修改的错误句子。标识必须定位到具体正文版本和段落，正文修改后重新评估。

标准模式中事实性内容缺关键来源时暂停相关生成并列出缺项；非事实创作/类比不强求虚构数据来源。快速模式减少操作次数，但不放宽事实真实性规则。

### 5.7 定稿与下游衔接（SCR-06，P0）

- “去配音”打开现有配音面板，带入指定正文版本；用户选择音色后提交，不自动产生付费任务。
- “生成封面”带入确认的标题、封面短句、主题和视觉提示，用户可改。
- “去发布准备”带入独立标题、简介、标签和正文来源；不能把全部创作简报塞进发布文案。
- 每个任务显示“来自哪份稿/哪个版本”；完成后可定位素材、入轨或替换当前产物。
- 正文后续改变时，对旧配音/字幕标记“对应旧稿”，提供重做受影响部分的入口。没有局部重做能力时明确显示全量重做范围。
- 有来源的最终正文与对应任务输入摘要应可对照，避免标题、语音和画面各用不同版本。
